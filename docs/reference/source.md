# Source (Ledger) Reference

The `source` tab is the backend database where all your raw transaction history resides. It is arguably the most vital tab for data integrity.

![Source Tab](/source.png)

It logs every transaction you make (date, amount, IBAN, category) and is the driver for the analytics displayed on the dashboard and many other parts of the financial template.

## Columns

The `source` tab contains several columns, many of which are populated automatically during the import process.

- `ref`: A unique identifier for the transaction (often automatically generated by combining IBAN, Date, and Amount to detect duplicates).
- `iban`: The account number the transaction belongs to.
- `date`: The date of the transaction.
- `amount`: The value of the transaction.
- `balance`: The running balance of your account after the transaction (if provided by your bank).
- `contra_account`: The name of the party you sent money to or received money from (e.g. "Starbucks", "Employer Inc.").
- `description`: The full text description provided by the bank.
- `comments`: A space for your own personal notes.
- `icon`: An emoji automatically or manually assigned based on the category.
- `category`: The designated spending bucket (e.g. "Food & Groceries", "Salary").
- `label`: Custom tags you can add to group related transactions across different categories (e.g., "#wedding2026").
- `import_date`: The date you imported the CSV.
- `hours`: If you have an hourly wage configured, this shows the equivalent hours worked to pay for the transaction.
- `disabled`: A `TRUE/FALSE` flag. If `TRUE`, the transaction is ignored in all dashboard calculations (useful for internal transfers between your own accounts).

## Best Practices

- **Only Edit Green Columns**: As per the [Legend](../getting-started/welcome), only columns with a light green background should be edited manually (such as `comments`, `category`, and `disabled`). 
- **Internal Transfers**: When transferring money between two of your own accounts (e.g. from Checking to Savings), both sides of the transaction will appear in the `source` tab. You should flag these as `disabled = TRUE` to prevent them from artificially inflating your income and expenses.
- **Duplicate Prevention**: The `ref` column is vital. Never delete or modify the `ref` column, as the import script uses it to ensure the same transaction isn't imported twice!
